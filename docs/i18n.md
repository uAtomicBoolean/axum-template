# Translations

[← README](../README.md)

Translations use [Fluent](https://projectfluent.org/) through
`fluent-templates`. The `locales/<language>/*.ftl` files are embedded in the
binary at compile time, so there is nothing to ship beside it.

- A missing key is displayed as-is and produces a warning in the logs.
  English is the fallback language (`fallback_language` in `src/i18n.rs`).
- Language negotiation: the `lang` cookie (set by `/lang/{code}`), then the
  browser's `Accept-Language` header, then `DEFAULT_LANG`. The header's `q=`
  weights decide, not the order they come in, so `fr;q=0.1, en;q=0.9` serves
  English.
- New language: create `locales/de/main.ftl` and add
  `Language { code: "de", label: "Deutsch" }` to `LANGUAGES` in `src/i18n.rs`.
  A test checks that every declared language resolves its keys, and that the
  locales all declare the same set — a key added to one and forgotten in
  another would otherwise fall back to English silently.
- Plurals are handled by Fluent according to each language:

  ```ftl
  home-note-count = { $count ->
      [one] You have { $count } note.
     *[other] You have { $count } notes.
  }
  ```

Dates go through `ctx.datetime()`, which uses the `format-datetime` key of the
current language. They are stored and printed in UTC, and the format says so:
the server never learns the visitor's timezone. The comment above that key in
each `.ftl` explains how to convert in the browser instead, from the
`<time datetime="…">` attribute the templates already emit.
